The namespace menu sits in the header, next to the search. Whatever you pick there applies everywhere in that cluster: the overview, every list, the Workloads and Metrics pages, and Helm releases.

## Pick a namespace

Open the menu and pick one, or **All namespaces**. Type to find a namespace in a long list. Namespaces that are being deleted have a **Terminating** badge.

You can also switch from the command palette: press <kbd>⌘</kbd><kbd>K</kbd> (<kbd>Ctrl</kbd><kbd>K</kbd> on Windows and Linux) and type the namespace's name. Its **Namespace** group lists **All namespaces** and every namespace.

## Pick several

To look at a few namespaces together, pick each one's box, or press <kbd>⌘</kbd><kbd>↵</kbd> on a namespace (<kbd>Ctrl</kbd><kbd>↵</kbd> on Windows and Linux): it's added, and the menu stays open. <kbd>↵</kbd>, or a click on a name, picks that one alone. The menu then says the two names, like **shop, staging**, where they fit, or how many, like **3 namespaces**.

Lists, Workloads, Events, Metrics and Helm releases show the picked namespaces together, up to 20. With 20 picked, the menu says "20 namespaces at most. Take one away to add another." A namespace you can't list can be typed and added like any other: <kbd>⌘</kbd><kbd>↵</kbd> on **Use namespace "shop"**.

Where some of them can't be read, the others still show, and a line above the list says which can't, and why: "Pods in shop aren’t shown: your account isn’t allowed to list them there.", or that a namespace isn't there any more.

The address carries them, like `?namespaces=shop,staging`, so a link opens on the same namespaces. A link that names more than 20 picks the first 20 in name order, and the menu says so.

## Rows from several namespaces

With more than one namespace, each row shows its namespace under its name, so you can tell `web` in `shop` from `web` in `staging`. Events are the exception: their list has no name column, so it doesn't show their namespace. Pick a namespace to see its events alone.

## Where it starts

When you open a cluster, Lumovi starts in:

1. The namespace you picked last time in that cluster, if any.
2. Otherwise, on the desktop, the one set in the cluster's [settings](/clusters/connect#cluster-settings).
3. Otherwise, the namespace set on the context in your kubeconfig.
4. Otherwise, **All namespaces**.

Your choice is remembered per cluster, so switching between clusters keeps each one where you left it. Setting a namespace in a cluster's settings forgets the one you last picked, so it opens there next time.

## If you can't list namespaces

Some accounts may use a few namespaces but not list them. When the list can't be read, the menu says *Namespaces couldn't be listed. Type a name to use it.* Type the namespace's name and choose **Use namespace "shop"**. The same works for any namespace that isn't in the list.

<Tip>
  If a page says **Access denied** with **All namespaces** picked, your account may only be allowed in some namespaces. Pick one of yours from the menu.
</Tip>

## Cluster-wide kinds

Some kinds don't live in a namespace: nodes, namespaces, volumes, storage classes, and cluster-scoped custom resources. On their pages the menu shows **Cluster-wide**, and the list shows everything, whichever namespace you picked. So does the page of a [plugin](/custom-resources/plugins) whose kinds are all cluster-wide.

The overview's node figures are cluster-wide too. Its workloads, pods and events follow the namespace you picked.

## The Namespaces page

**Namespaces** (in the sidebar under **Cluster**, or <kbd>G</kbd> then <kbd>M</kbd>) lists every namespace with its status: <span className="lumovi-status healthy">Active</span>, or the phase it's in, like <span className="lumovi-status warning">Terminating</span>.

Open one for its labels, annotations and events. Deleting a namespace deletes everything in it, so Lumovi asks you to type its name first. See [Changing things safely](/changes/safely).
