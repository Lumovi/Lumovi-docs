The desktop app reads clusters from the same place `kubectl` does, and keeps your credentials on your computer. You don't need `kubectl` installed.

<Card title="Download Lumovi" icon="download" href="https://lumovi.dev/#download" horizontal cta="lumovi.dev">
  The website picks the right installer for your computer. Every installer is also on the [latest GitHub release](https://github.com/Lumovi/Lumovi/releases/latest).
</Card>

## Install

<Tabs>
  <Tab title="macOS" icon="apple">
    For macOS 13 (Ventura) or later, on Apple silicon and Intel. The app is signed and notarized by Apple.

    With [Homebrew](https://brew.sh), name the cask in full:

    ```bash
    brew install --cask lumovi/tap/lumovi
    ```

    It installs the same disk image, from [Lumovi's tap](https://github.com/Lumovi/homebrew-tap). Lumovi keeps itself up to date as before, so `brew upgrade` leaves it alone. `brew uninstall --cask --zap lumovi` also removes its settings, its own audit log, caches and logs.

    Or download it yourself:

    <Steps>
      <Step title="Download the disk image">
        Pick the one for your Mac:

        | Mac | File |
        | --- | --- |
        | Apple silicon (M1 and later) | `Lumovi-<version>-mac-arm64.dmg` |
        | Intel | `Lumovi-<version>-mac-x64.dmg` |

        Not sure which you have? Choose **Apple menu → About This Mac**, and look at **Chip** or **Processor**.
      </Step>
      <Step title="Drag Lumovi to Applications">
        Open the `.dmg`, and drag **Lumovi** into the **Applications** folder.
      </Step>
      <Step title="Open it">
        Open Lumovi from Applications, Launchpad or Spotlight. It finds your clusters straight away.
      </Step>
    </Steps>

    <Note>
      Prefer a `.zip`? Each release has one for Apple silicon and one for Intel, next to the disk images.
    </Note>
  </Tab>
  <Tab title="Windows" icon="app-window">
    For Windows 10 or later. One installer covers x64 and arm64.

    <Steps>
      <Step title="Download the installer">
        Download `Lumovi-<version>-win.exe`.
      </Step>
      <Step title="Run it">
        Open the installer, and follow its steps. It asks whether to install Lumovi only for you or for anyone who uses the computer; installing it for everyone needs an administrator. You can choose the folder Lumovi goes in, and it adds a shortcut to your desktop.

        <Warning>
          The Windows installer isn't code-signed yet, so Windows may say it protected your PC. Choose **More info**, then **Run anyway**. You can check the file first: see [Verify your download](#verify-your-download).
        </Warning>
      </Step>
    </Steps>
  </Tab>
  <Tab title="Linux" icon="terminal">
    For a recent 64-bit distribution, on x64 and arm64.

    | Format | x64 | arm64 |
    | --- | --- | --- |
    | AppImage, for any distribution | `linux-x86_64.AppImage` | `linux-arm64.AppImage` |
    | Debian, Ubuntu | `linux-amd64.deb` | `linux-arm64.deb` |
    | Fedora, RHEL, openSUSE | `linux-x86_64.rpm` | `linux-aarch64.rpm` |

    Each file name starts with `Lumovi-<version>-`.

    <CodeGroup>
      ```bash AppImage
      chmod +x Lumovi-*-linux-x86_64.AppImage
      ./Lumovi-*-linux-x86_64.AppImage
      ```

      ```bash Debian and Ubuntu
      sudo apt install ./Lumovi-*-linux-amd64.deb
      ```

      ```bash Fedora and RHEL
      sudo dnf install ./Lumovi-*-linux-x86_64.rpm
      ```
    </CodeGroup>
  </Tab>
</Tabs>

## Staying up to date

Lumovi keeps itself up to date. It looks for a new version shortly after it starts and every few hours after that, downloads it in the background, and installs it when you quit. When one is ready, a notice says so, with **Restart now** and **What's new**. Close it, and the new version installs when you quit.

- **Help → Check for Updates…** looks right away, and says what it found: *Lumovi is up to date*, *Downloading Lumovi …*, or *Couldn't check for updates*, with the reason.
- **Help → Check for Updates Automatically** turns the background checks off.

Your organization's [policy](/desktop/policy) can leave updates to IT, which then deploys new versions itself: Lumovi neither looks for them nor installs them, **Check for Updates…** reads **Updates Are Set by Your Organization**, and both items are disabled.

Installed with Homebrew, Lumovi updates itself the same way. On Linux, the AppImage replaces itself. A `.deb` or `.rpm` install updates through your package manager, so installing a new version asks for an administrator password.

New versions come from the project's [GitHub releases](https://github.com/Lumovi/Lumovi/releases), over HTTPS. Each download is checked against the checksum the release lists, and on macOS the new version must carry the same Developer ID signature. A copy that can't update itself says so when you check: install new versions of it from the releases page.

## Verify your download

Every release lists the SHA-256 checksum of each installer in `SHA256SUMS.txt`. Each installer has a signed build provenance attestation, which says it was built by Lumovi's release workflow from the release's commit, and an attested bill of materials: `Lumovi-<version>.cdx.json` (CycloneDX), every package the app bundles or ships, Electron, and the helm it ships with (4.3.0), on the release too.

<CodeGroup>
  ```bash Checksum (macOS, Linux)
  # In the folder with the installer and SHA256SUMS.txt
  shasum -a 256 --ignore-missing -c SHA256SUMS.txt
  ```

  ```powershell Checksum (Windows)
  Get-FileHash .\Lumovi-{{version}}-win.exe -Algorithm SHA256
  # Compare with the line for this file in SHA256SUMS.txt
  ```

  ```bash Provenance and bill of materials (GitHub CLI)
  # Built by the release workflow, from main.
  signer=(--repo Lumovi/Lumovi --signer-workflow Lumovi/Lumovi/.github/workflows/release.yml
    --source-ref refs/heads/main)

  # An installer: built there, and what it's made of (the release's Lumovi-<version>.cdx.json).
  gh attestation verify Lumovi-{{version}}-mac-arm64.dmg "${signer[@]}"
  gh attestation verify Lumovi-{{version}}-mac-arm64.dmg "${signer[@]}" \
    --predicate-type https://cyclonedx.org/bom
  ```
</CodeGroup>

## Requirements

<div className="lumovi-facts">
  <div><span className="lumovi-label">macOS</span><span className="lumovi-value">13 (Ventura) or later</span></div>
  <div><span className="lumovi-label">Windows</span><span className="lumovi-value">10 or later</span></div>
  <div><span className="lumovi-label">Linux</span><span className="lumovi-value">Recent, 64-bit</span></div>
  <div><span className="lumovi-label">Kubernetes</span><span className="lumovi-value">1.25 or later</span></div>
</div>

- **Neither kubectl nor [Helm](https://helm.sh) is needed.** Lumovi talks to the API server itself, and ships with the helm its Helm actions run. Each [terminal](/debug/terminal#a-kubectl-that-matches-the-cluster) gets a kubectl that matches its cluster.
- **Kubernetes 1.27 or later** lets Lumovi explain fields from the cluster's own OpenAPI schema. Older clusters work, without the explanations.

Want to build it yourself? See [Build from source](/reference/build-from-source).
