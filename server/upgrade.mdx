The desktop app updates itself. In a cluster, Lumovi is upgraded like anything else Helm installed: you upgrade its chart. The chart is released with Lumovi itself, so the chart's version is the app's.

## Upgrade

<Steps>
  <Step title="See what's new">
    Each version's changes are in the [changelog](/changelog) and on [GitHub releases](https://github.com/Lumovi/Lumovi/releases).
  </Step>
  <Step title="Upgrade the chart">
    <CodeGroup>
      ```bash With your values file
      helm upgrade lumovi oci://ghcr.io/lumovi/charts/lumovi \
        --namespace lumovi --values values.yaml
      ```

      ```bash To a particular version
      helm upgrade lumovi oci://ghcr.io/lumovi/charts/lumovi \
        --namespace lumovi --values values.yaml --version {{version}}
      ```

      ```bash Keeping the values you set before
      helm upgrade lumovi oci://ghcr.io/lumovi/charts/lumovi \
        --namespace lumovi --reuse-values
      ```
    </CodeGroup>

    Without `--version`, Helm installs the latest. The image's tag follows the chart unless you set `image.tag`.
  </Step>
  <Step title="Check it started">
    ```bash
    kubectl rollout status --namespace lumovi deployment/lumovi
    kubectl logs --namespace lumovi deployment/lumovi
    ```

    Its line `Lumovi … shows …` names the version that's running. The log's lines of JSON, with `"type":"lumovi.audit"`, are its [audit events](/server/audit-log#on-the-server’s-output).
  </Step>
</Steps>

## What people see

A new pod signs nobody out, with [one exception](/server/auth/single-sign-on#when-the-api-server-trusts-the-provider) where single sign-on passes people's tokens on: Lumovi keeps sessions, and the AI assistants people allowed, in a Secret the chart makes (`auth.keepSessions`), which upgrades leave as it is. Open pages reconnect to the new pod by themselves, and carry on. AI assistants open a new connection; those that pass their person's own token on wait until that person opens Lumovi again. See [Across restarts](/server/security#across-restarts). With `auth.keepSessions: false`, a new pod signs everyone out, and open pages show the sign-in page.

The same goes for any change that replaces the pod: changing a setting, or the [plugins everyone sees](/server/plugins).

<Note>
  For the same reason the chart runs one replica, and refuses more while AI assistants or the audit history's volume are on, as they are by default. See `replicaCount` in [Helm values](/server/helm-values#kubernetes-objects).
</Note>

## When the client secret changes

A change to a Secret's contents doesn't replace the pod. Lumovi reads the single sign-on client's secret from an environment variable, when the pod starts, so it keeps the old one until it restarts. That's the case when you change `auth.oidc.clientSecret` and upgrade (the chart changes its Secret, not the pod), and when you change the Secret that `auth.oidc.existingSecret` names.

Restart Lumovi so it reads the new secret:

```bash
kubectl rollout restart --namespace lumovi deployment/lumovi
```

Like any restart, this signs nobody out. A fleet's list of agents, in the Secret that `fleet.agentsSecret` names, is read the same way, when the pod starts: restart Lumovi after changing it too. Its kubeconfig, in `fleet.kubeconfigSecret`, and the Secrets it reads with `fleet.secrets` are read again by themselves, without a restart.

## A fleet

Upgrade a fleet's Lumovi as above, or, where it runs from the image alone (with Docker, or on a platform like [Sevalla](/server/fleet/sevalla)), by changing the image's tag.

- **Its agents connect again by themselves.** Stopping, Lumovi closes their connections, and each agent tries again a second later, then less and less often, until the new one answers. Lumovi's log names each agent's version as it connects, like `The agent of private-eu connected (Lumovi {{version}})`.
- **Members and agents are releases of their own**, in their own clusters. Upgrade each there, the same way, with its own values or `--reuse-values`.

## Roll back

Helm keeps the previous revision, so going back is one command:

```bash
helm rollback lumovi --namespace lumovi
```

`helm history lumovi --namespace lumovi` lists the revisions, and `helm rollback lumovi <revision> --namespace lumovi` goes back to a particular one.
