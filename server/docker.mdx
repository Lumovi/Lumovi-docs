The image also runs on its own, outside the cluster it shows: on a machine of its own, say, as a dashboard for a cluster a team shares. Give it a kubeconfig, and it shows one of its contexts to everyone who signs in, the same way it would from inside the cluster.

```bash
docker run --rm -p 8080:8080 \
  -v "$PWD/kubeconfig:/kubeconfig:ro" -e KUBECONFIG=/kubeconfig \
  -e LUMOVI_CONTEXT=production \
  ghcr.io/lumovi/lumovi
```

Then open [http://localhost:8080](http://localhost:8080).

- `LUMOVI_CONTEXT` picks the context to show; without it, the kubeconfig's current context.
- The cluster is called by its context's name, unless `LUMOVI_CLUSTER_NAME` says otherwise.
- Lumovi listens on port 8080 (`LUMOVI_PORT`), and answers `/healthz` for health checks. When `LUMOVI_PORT` isn't set, it listens on `PORT` if that's set, as platforms that run containers set it.

Every setting is an environment variable here: see [Configuration](/server/configuration).

## Whose credentials it uses

That depends on how people sign in, exactly as in a cluster:

- **With tokens** (the default), people's requests carry their own tokens. The kubeconfig only says where the cluster is and how to trust its certificate.
- **With single sign-on or a proxy**, Lumovi uses the kubeconfig's credentials to impersonate people. Give it a service account's, with permission to impersonate users and groups, and nothing more.

<Warning>
  The image has only Node.js and helm, so credential plugins like `aws eks get-token`, `gke-gcloud-auth-plugin` or `kubelogin` aren't in it. Use a kubeconfig whose user has a token or a client certificate.
</Warning>

Paths in a kubeconfig (to a certificate, say) are read relative to the kubeconfig's own folder, so mount those files next to it, or embed them with the `*-data` fields. The image runs as a non-root user (UID 65532), so make sure that user can read what you mount.

## With single sign-on

```bash
docker run --rm -p 8080:8080 \
  -v "$PWD/kubeconfig:/kubeconfig:ro" -e KUBECONFIG=/kubeconfig \
  -e LUMOVI_CONTEXT=production \
  -e LUMOVI_URL=https://lumovi.example.com \
  -e LUMOVI_AUTH=oidc \
  -e LUMOVI_OIDC_ISSUER=https://dex.example.com \
  -e LUMOVI_OIDC_CLIENT_ID=lumovi \
  -e LUMOVI_OIDC_CLIENT_SECRET \
  -e LUMOVI_USERNAME_PREFIX=oidc: \
  -e LUMOVI_GROUPS_PREFIX=oidc: \
  ghcr.io/lumovi/lumovi
```

`-e LUMOVI_OIDC_CLIENT_SECRET` without a value passes the variable on from your shell, so the secret stays out of your shell history. Put TLS in front of Lumovi with a reverse proxy, and set `LUMOVI_URL` to the address people open. See [Single sign-on](/server/auth/single-sign-on) for registering Lumovi with your provider.

## A fleet

To show many clusters, give Lumovi a kubeconfig whose contexts are the clusters, with credentials that may only impersonate, instead of `KUBECONFIG`. It needs no Kubernetes of its own, and [single sign-on](/server/auth/single-sign-on) or a proxy, as a fleet always does:

```bash
docker run -d --restart unless-stopped -p 8080:8080 \
  -v "$PWD/fleet:/etc/lumovi/fleet:ro" \
  -e LUMOVI_FLEET_KUBECONFIG_FILE=/etc/lumovi/fleet/kubeconfig \
  -e LUMOVI_URL=https://lumovi.example.com \
  -e LUMOVI_AUTH=oidc \
  -e LUMOVI_OIDC_ISSUER=https://dex.example.com \
  -e LUMOVI_OIDC_CLIENT_ID=lumovi \
  -e LUMOVI_OIDC_CLIENT_SECRET \
  ghcr.io/lumovi/lumovi:{{version}}
```

Lumovi reads the file again every 30 seconds, so mount its folder rather than the file: an editor that replaces the file leaves a file mounted on its own as it was. Without files to mount, put the kubeconfig in `LUMOVI_FLEET_KUBECONFIG` instead, as YAML or encoded in base64, as on [Sevalla](/server/fleet/sevalla). Clusters it can't reach join through an [agent](/server/fleet/agents) that dials it, listed in `LUMOVI_FLEET_AGENTS`. See [A fleet of clusters](/server/fleet).

## Pin a version

Without a tag, Docker pulls `latest`, the latest release. Pin a version to know what runs:

```bash
docker run --rm -p 8080:8080 \
  -v "$PWD/kubeconfig:/kubeconfig:ro" -e KUBECONFIG=/kubeconfig \
  ghcr.io/lumovi/lumovi:{{version}}
```

Sessions live in Lumovi's memory, so restarting the container signs everyone out.
